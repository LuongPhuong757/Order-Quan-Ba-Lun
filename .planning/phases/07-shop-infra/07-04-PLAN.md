Tạo script chạy lại được, exit code khác 0 khi phát hiện rò.

```sh
#!/bin/sh
# M2.D-64 — bundle của order.<domain> KHÔNG được chứa route/code trang quản lý.
# Chạy sau khi build: pnpm --filter @order/shop build && sh scripts/check-shop-bundle.sh
set -e
DIST="apps/shop/dist"
[ -d "$DIST" ] || { echo "SKIP: chưa build $DIST"; exit 1; }
FORBIDDEN="/dashboard /kitchen /admin/ TablesManagementPage MenuManagementPage AdminAuditPage AdminUsersPage"
FAIL=0
for s in $FORBIDDEN; do
  if grep -rIlF -- "$s" "$DIST" >/dev/null 2>&1; then
    echo "LEAK: '$s' xuất hiện trong $DIST"; grep -rIlF -- "$s" "$DIST"; FAIL=1
  fi
done
[ "$FAIL" = 0 ] && echo "OK: bundle khách sạch (đã kiểm $(echo $FORBIDDEN | wc -w) chuỗi)"
exit $FAIL
```

Lưu ý khi làm:
1. Kiểm danh sách `FORBIDDEN` với thực tế `apps/web/src/pages/` — dùng đúng tên page component đang có (`DashboardPage`, `KitchenPage`, `TablesManagementPage`, `MenuManagementPage`, `AdminAuditPage`, `AdminUsersPage`, `AccountPage`, `SetupPage`, `RecoverPage`). Chọn những chuỗi **đặc trưng cho quản lý**, đừng chọn chuỗi chung như `Page` sẽ báo giả.
2. **Cẩn thận false positive:** `apps/shop` có `HistoryPage` và `apps/web` cũng có `HistoryPage` — KHÔNG đưa `HistoryPage` vào danh sách cấm.
3. Chạy thử ngay: `pnpm --filter @order/shop build && sh scripts/check-shop-bundle.sh` → phải in `OK`.
4. Chạy thử ngược để chứng minh guard thật sự bắt được: tạm thêm chuỗi `/dashboard` vào một file trong `apps/shop/src`, build lại, xác nhận script **exit 1**, rồi **hoàn nguyên**. Ghi cả 2 output vào SUMMARY.
5. `chmod +x scripts/check-shop-bundle.sh`. Nếu thư mục `scripts/` chưa có thì tạo.

<task type="auto">
  <name>Task 2: Site block Caddy cho order.&lt;domain&gt;</name>
  <files>Caddyfile</files>
  <read_first>Caddyfile, .planning/intel/constraints.md</read_first>
  <action>
Thêm block **mới bên dưới** block apex hiện có. KHÔNG gộp `order.{$DOMAIN}` vào danh sách hostname của block apex — hai bên cần `Permissions-Policy` khác nhau (D-13).

```
# M2.D-69 — site block riêng cho trang khách.
# Tách khỏi apex vì geolocation phải bật cho khách (nút "Chia sẻ vị trí") nhưng
# phải tắt ở trang quản lý. Không gộp hostname vào block trên.
order.{$DOMAIN} {
    log {
        output stdout
        format console
    }

    reverse_proxy api:3001 {
        header_up X-Real-IP {remote_host}
        header_up X-Forwarded-For {remote_host}
        header_up X-Forwarded-Proto {scheme}
    }

    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Frame-Options "DENY"
        X-Content-Type-Options "nosniff"
        # C-INFRA-03 — order_token là bearer credential nằm trong URL /o/<token>.
        # no-referrer để token không rò sang site ngoài qua header Referer.
        Referrer-Policy "no-referrer"
        # M2.D-69 — bật geolocation cho chính origin này. Block apex giữ geolocation=().
        Permissions-Policy "geolocation=(self), camera=(), microphone=()"
    }

    encode zstd gzip
}
```

Bắt buộc:
1. **KHÔNG sửa block apex.** Xác nhận sau khi sửa, block apex vẫn còn nguyên `Permissions-Policy "geolocation=(), camera=(self), microphone=()"` và `Referrer-Policy "strict-origin-when-cross-origin"`.
2. KHÔNG thêm `www.order.` (D-16).
3. Không thêm `tls` block nào — Caddy tự cấp cert, giữ nguyên hành vi như apex.
4. Validate cú pháp **không cần apply**: `docker run --rm -v "$PWD/Caddyfile:/etc/caddy/Caddyfile" caddy:2-alpine caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile` (cần `DOMAIN` — truyền `-e DOMAIN=quanbalun.site`). Nếu không có Docker thì `caddy fmt --diff Caddyfile` hoặc bỏ qua và ghi rõ trong SUMMARY là chưa validate được.
5. **KHÔNG** `docker compose up`, **KHÔNG** reload Caddy đang chạy, **KHÔNG** ssh vào VPS (C-LOCAL-01).
