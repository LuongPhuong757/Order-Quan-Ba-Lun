  <action>
    Đổi `storage: diskStorage({...})` của `FileInterceptor` trong `uploadImage` thành `memoryStorage()`
    (import từ `multer`) và tự ghi file sau khi xử lý. Lý do (ASVS V12): file gốc chưa qua kiểm tra
    không bao giờ được ghi ra đĩa; sharp decode buffer trong RAM rồi mới xuất file đã chuẩn hoá.

    **Giữ nguyên tuyệt đối 4 thứ:** hằng `UPLOAD_DIR = 'uploads/menu'`, `ALLOWED_MIMES`,
    `MAX_FILE_BYTES` (5 MB), và cách sinh tên file bằng
    `` `${Date.now()}-${randomBytes(6).toString('hex')}` `` — đây là lớp chống path traversal đã có,
    không được đổi khi thêm sharp. Chỉ **cố định phần mở rộng thành `.webp`** bất kể mime gốc, thay cho
    đoạn `extname(file.originalname)` + `replace(/[^a-z0-9.]/g,'')` cũ (không còn cần vì đuôi không lấy
    từ input người dùng nữa).

    Pipeline trong `uploadImage`:
    1. Nếu không có `file` → giữ nguyên `BadRequestException({ code: 'BAD_REQUEST', message: 'Thiếu file ảnh' })`.
    2. `sharp(file.buffer)` → `.rotate()` (áp EXIF orientation — ảnh chụp dọc bằng điện thoại không bị
       nằm ngang; `.rotate()` không tham số nghĩa là "theo EXIF") → `.resize({ width: 800, withoutEnlargement: true })`
       (ảnh nhỏ hơn 800px không bị phóng to thành mờ) → `.webp({ quality: 82 })` → `.toFile(join(UPLOAD_DIR, name))`.
    3. Nếu `sharp` throw (file không phải ảnh thật dù mime hợp lệ — mime do client khai, không đáng tin)
       → `BadRequestException({ code: 'BAD_REQUEST', message: 'Ảnh không đọc được, vui lòng chọn ảnh khác' })`.
       Đây là lớp kiểm nội dung thật, mạnh hơn `ALLOWED_MIMES` vốn chỉ đọc header client gửi.
    4. Trả **đúng shape cũ**: `{ data: { url: `/uploads/menu/${name}` } }` với `name` đã có đuôi
       `.webp`. `apps/web` không phải sửa gì.
    Thêm import `sharp` (default import) và `join` từ `node:path`; bỏ import `extname` nếu không còn chỗ
    dùng nào khác trong file (kiểm bằng grep trước khi xoá). Cập nhật docblock của method: ghi rõ D-12,
    kích thước đích 800px, định dạng webp, và lý do dùng `memoryStorage`.
  </action>
